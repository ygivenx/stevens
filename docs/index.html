Thesis

Future knowledge workers won't mostly write; they'll read, listen and absorb. Stevens takes in what you learn off the clock — talks, readings, conference captures from Ray-Ban Meta glasses — and connects it to the work decision in front of you, with a source on every sentence.

Stevens is named after the butler in The Remains of the Day: he knows the bigger picture, prepares you before the delegation arrives, and is discreet about everything. This is not RAG over notes. The new parts are the bridge (off-the-clock learning → work decision) and the access rule that is enforced, provable and inspectable.

The demo persona is a VC Associate at a fictional firm; the pitch generalizes to an engineer reading papers before a design review.

The 3-minute demo

  1. Hook (0:00). One line of the thesis.
  2. Capture (0:20). Last week's conference as real Ray-Ban Meta POV footage: talk audio → live Voice Transcribe with speaker labels and timestamps; glasses photo of a slide → live Spark vision. Both land in the personal vault.
  3. Unprompted brief (0:50). For tomorrow's second Helios meeting. The bridge: the deck claims net churn of 1.8% (Enterprise · Fact); at the Oct 20 talk, Speaker 2 at 14:32: "mid-market churn in this category runs 6–8%" (Personal · Fact); so ask how they define churn (Inference). The personal quote carries a chip: visible to you only.
  4. Associate asks (1:25) "Should we take the second meeting?" The answer comes from visible data plus the privy verdict: Recommendation: hold until a Partner reviews. Stevens weighed information you are not privy to. An escalation is drafted to a Partner. It has no content, and it shows personal sources as owner-only.
  5. Boundary inspector (1:50). For each model call: what went in, what was withheld, and which policy rule applied; raw vs assembled token counts. The answer call contains no partner memo; the Associate sees "1 privy check ran — contents hidden"; web search was off for every enterprise call.
  6. Release and approval (2:15). The Associate clicks Share with the firm on the churn quote, which logs personal.released. Switch to Partner. The Partner sees the conflict memo (Helios competes with portfolio company Lumen) and the released quote; every other personal source shows as owner-only. The Partner approves "take the meeting after conflict review," and the decision is logged.
  7. Close (2:50). "Same Stevens for the engineer before a design review." Tagline.

The access rule

Personal

Stevens is your agent, so he sees everything in your personal vault. Personal data never reaches the firm unless you release it. Reaching the firm means: stored in an enterprise record, included in an escalation or an approved decision, or shown to anyone but you. Each release covers one quote and is logged. You seeing your own quote in your own brief is not a crossing. Nothing from the firm is ever written into your personal vault.

Enterprise

For each user, every enterprise source has one access level:

LevelWhat Stevens may doWhat the user sees
visibleRead and quote itThe content
privyReason over it on the user's behalfOnly its effect: a verdict and where it routes, never content
excludedNothingNothing (legal walls, insider information)

An Associate's agent is privy to the Partners' memos: it knows of the Helios conflict, so it recommends "hold until Partner review," and the Associate never learns why.

One mechanism at both edges

Content crosses an edge only through a narrow, typed channel. Privy knowledge reaches the user only as a fixed Verdict with no string fields. Personal content reaches the firm only as a quote the owner released. A weak model is never asked to keep a secret in free text. Known, accepted leak: privy reveals that something matters and which way it pushes — fine for partner memos, which is why legal walls are excluded, not privy.

Server architecture

A Hono server on :8787 owns the boundary: the vaults, policy, assembler, pipeline, ledger, and every Meta call. The browser receives only viewer-filtered JSON. The Vite UI on :5173 proxies /api to the server and adds no key. MODEL_API_KEY exists only in .env.local and the server process.

  • Policy as data: a rules table maps (vault, classification, owner, viewer role, purpose) to access; policy() is a lookup, and the inspector shows the rule ID behind every included or withheld source.
  • Context assembler: the only path into a model call; emits a manifest of included and withheld sources, the web-search flag, and raw vs assembled tokens.
  • Release gate: escalations, approved decisions, and non-owner responses pass through it; unreleased personal text renders "Personal source (owner only)".
  • Fail closed: a failed privy step yields hold plus escalation; a response that cannot pass the gate is withheld.
  • Durable pipeline: every stage call has a stage key and is reused if complete; events append to data/ledger.jsonl before the UI hears of them; a crash resumes with no repeated paid call; replay never re-calls the API.
  • Stevens API: GET /api/state (viewer-filtered projection), GET /api/events (SSE: transcribing → extracting → bridging → drafting), POST ingest / ask / release / approve / reject, GET /api/media/:sourceId (policy-checked; fixtures are never served statically). Every request carries X-Viewer-Role.

  • Simulated and labeled: the VC firm and its data (fictional), the staged talk, sign-in (a role switcher labeled "simulated sign-in"), and permission scopes modeled on Meta's Personal Agent Protocol.
